## Status vocabulary

| Status | Meaning |
| --- | --- |
| PASS | The listed tests ran against the exact recorded revision, exit code 0, with the negative control behaving as intended. |
| FAIL | A listed test ran and failed. A defect is open with the owning agent. |
| BLOCKED | A required capability is absent (for example no real local provider). The exact blocker is written in the Evidence column. Never counted as pass. |
| NOT RUN | Test is planned or written but there is no recorded run for the current revision. Never counted as pass. |
| PARTIAL | Some listed tests ran and passed (see the run ledger); others are NOT RUN. Never counted as pass. |
| PENDING_HUMAN_RECEIPT | Needs a human receipt. No agent may mark it PASS (AC-11 only). |

Rules applied to every row:
- A simulator, fixture or in-memory fake never satisfies a live criterion (AC-07). Only a real local provider receipt does.
- Any NOT RUN, PARTIAL or BLOCKED row prevents the claim "matrix passed".
- A criterion is behavior-proven only when both its happy and its sad path rows are PASS.
- Test IDs are `file :: test name` and are the real names as they appear in the run. A row is PASS only for the revisions listed in the run ledger; a later commit that touches covered code needs a new run.
- Default tests use the fixed UTC clock `2026-01-15T12:00:00.000Z`, synthetic UUIDs from `fixtures/` and planted fake secrets only.
- Receipts in this file are QA runs (command, exit code, UTC from `date -u`, full SHA, dirty-tree note). Builder smoke runs (for example the backend's own CouchDB run at `515c4f8`) are not independent evidence and are not counted.
